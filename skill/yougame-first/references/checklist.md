# Критерии готовности и формулировки

Что именно проверяет `yg_ready` и как объяснять результат пользователю.

## Требования гейта

Зависят от типа задачи — его определяет `yg_plan` по формулировке.

### `implement` / `port` / `fix` — полный набор

| Требование | Чем закрывается |
|---|---|
| Минимум два источника с форума | `yg_search` → `yg_thread` → `yg_note` с полем `sources` |
| Решено, брать готовый инструмент или писать своё | `yg_tools`, затем `yg_ready` с `toolIds`, либо `yg_note kind="gap"` с объяснением, почему готовое не подходит |
| Есть источник с кодом | источник помечен `kind: "code"` (разделы «Исходники …», префикс «Исходник») |
| У одного источника прочитаны комментарии | `yg_thread` без `firstPostOnly`, источник помечен `commentsRead: true` |
| Записаны конкретные факты | `yg_note kind="fact"` или `kind="version"` по каждому пункту `mustKnow` из плана |

### `find` / `explore` — облегчённый набор

Достаточно одного прочитанного источника и решения по инструментам.
Пользователь просил найти или разобраться, а не построить — не устраивай полный цикл.

## Что считается закрытым вопросом

Пункты `mustKnow` из `yg_plan` — это не формальность, а то, без чего код гарантированно
не заработает. Типичные:

- **версия** игры / движка / лоадера / рантайма;
- **формат цели**: Mono или IL2CPP, обфусцирован ли jar, стоит ли протектор на бинаре;
- **точка входа**: агент до запуска, миксин на загрузке класса, инъекция в живой процесс,
  внешнее чтение памяти;
- **срок годности**: оффсеты и схемы живут до ближайшего патча игры — это надо сказать
  пользователю, а не молча зашить константы.

Каждый закрытый пункт — отдельный `yg_note`. Незакрытый пункт, по которому на форуме
пусто, — `yg_note kind="gap"`.

## Пробел (`gap`) — нормальный результат

Записывай `gap`, когда:

- поиск по всем запросам плана дал пустоту или только нерелевантное;
- нужный раздел закрыт, а пользователь не хочет входить;
- контент за хайдом, который открывается только рангом аккаунта;
- готового инструмента под эту версию/формат нет.

`gap` снимает соответствующее требование гейта. Взамен ты обязан сказать пользователю,
чего именно не нашёл — это и есть честная цена решения «пишу с нуля».

## `force` — крайний случай

`yg_ready` с `force: true` и `reason` проходит гейт без выполненных требований.
Причина сохраняется в сессии и попадает в `yg_report`. Условия применения:

- пользователь прямо сказал «не ищи, пиши сразу» — тогда `reason` это и фиксирует;
- форум недоступен (сеть, бан, техработы);
- задача срочная и пользователь принял риск.

Использовал `force` — обязан начать ответ с фразы уровня: «ресерч не проводил
(<причина>), решение написано с нуля, вот допущения». Молча пройти гейт нельзя.

## Формулировки для ответа

**Нашлось готовое:**
> Своё писать не нужно: <инструмент> делает ровно это. Вот как применить к твоему
> случаю: … Ограничения, о которых пишут в теме <ссылка>: …

**Нашлась механика, но не код:**
> Механику собрал из <2–3 ссылки>. Готового решения под твою версию нет,
> написал сам; спорные места: …

**Не нашлось ничего:**
> На форуме по этому пусто (искал: <запросы>). Пишу с нуля, опираясь на <общая теория>.
> Что стоит проверить в первую очередь: …

**Источник устарел:**
> Тема <ссылка> описывает это для версии X, у тебя Y. В комментариях пишут, что <фикс>.
> Учёл это так: …
